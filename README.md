# AURA MVP — рабочий прототип

Собрано по AURA_MVP_Product_Technical_Spec_v1_1, с одним отличием от спеки:
**фронтенд сделан как PWA (сайт + "Установить на экран"), а не нативный iOS/SwiftUI**,
как просил заказчик.

## Структура

```
aura/                (корень репозитория)
  frontend/         PWA — открой в браузере или установи на телефон (AURA-брендинг, рабочий fallback)
    index.html       6 экранов из §7: onboarding → home → camera → card → progress → recap
    app.js            state machine, mock-распознавание, локализация, recap-канвас
    data.js            датасет Top 100 (реальные работы Орсэ, Wikidata) — Layer 1 факты + Top 20 editorial-черновик
    styles.css        design tokens ровно по §15: #FAFAF9 / #111111 / радиус 20px
    manifest.json + sw.js + icons/    делают сайт устанавливаемым PWA
  web/               Next.js — новый дизайн ELYIO, тот же backend (см. раздел ниже)
  backend/           FastAPI-каркас (общий для frontend/ и web/)
    requirements.txt
    app/models.py     схема БД — все сущности из §9.2 (2-layer: факты vs editorial)
    app/main.py       эндпоинты из §12 (/v1/recognize, /v1/visits, ...)
  design/            дизайн-спека ELYIO (ELYIO-FINAL-PROMPT.md и др.) — источник правды для web/
  .env.example        шаблон для .env (см. Setup)
```

## Setup (для нового человека в репозитории)

Требуется Python 3.11+ (не 3.14 — на некоторых системах у него оказывается битый
stdlib, см. предыдущий опыт запуска) и любой современный браузер для фронтенда.

```bash
# 1. Склонировать репозиторий
git clone https://github.com/shopqrepublik/aura.git
cd aura

# 2. Создать и активировать venv, поставить зависимости backend
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS/Linux
pip install -r backend/requirements.txt

# 3. Секреты — скопировать .env.example в .env и вписать реальный ключ
copy .env.example .env         # Windows
# cp .env.example .env         # macOS/Linux
# затем открой .env и подставь свой OPENAI_API_KEY (без него backend
# работает в mock-режиме — см. "Распознавание" ниже)

# 4. Запустить backend (порт 8090 — см. заметку про порт 8000 ниже)
cd backend
uvicorn app.main:app --reload --port 8090

# 5. В отдельном терминале — запустить frontend (ничего ставить не нужно,
#    это чистый HTML/CSS/JS без npm/сборки)
cd frontend
python -m http.server 8080
```

Открой `http://localhost:8080` — фронтенд работает с реальным backend на
`:8090` (см. `BACKEND_URL` в `frontend/app.js`), а если backend недоступен —
автоматически откатывается на клиентский mock, так что UI-разработку можно
вести вообще без бэкенда.

## Как посмотреть прямо сейчас

Фронтенд не требует бэкенда — распознавание замокано на клиенте (см. `mockRecognize()`
в app.js), так что весь флоу кликается локально:

```bash
cd frontend
python3 -m http.server 8080
```
Открой `http://localhost:8080` на телефоне (в одной Wi-Fi сети с компом) —
Safari/Chrome покажет "Добавить на экран Домой", получишь иконку как у обычного приложения.

## Распознавание — как это работает сейчас

Вместо DINOv2/CLIP + FAISS (§8.2) используется vision-LLM с закрытым списком кандидатов:
фото + каталог из 100 реальных работ (id/автор/название/год) уходят в OpenAI (`gpt-4o`,
Chat Completions API с `response_format={"type": "json_object"}` — гарантирует валидный JSON
без ручного парсинга текста), модель обязана ответить ТОЛЬКО одним из id из каталога или
`null` — так сохраняется принцип retrieval на контролируемом наборе (§8.1), а не открытая
генерация. Это дешевле и быстрее в разработке, чем сбор эталонных снимков и обучение
embeddings, но дороже и медленнее на каждый скан в проде — стоит протестировать точность
на всех 100 работах, включая похожие по стилю картины одного автора, прежде чем считать
вопрос закрытым.

**Без `OPENAI_API_KEY` бэкенд отвечает рандомным мок-ответом** — фронтенд при этом
всё равно работает (полезно при доработке UI без ключа).

## Content policy — Kids mode (решение продукта, зафиксировано)

Из 100 работ каталога 4 получили специальную обработку в Kids mode; остальные 96 — без
ограничений. Правило действует и для будущих расширений каталога: новую работу с явной
наготой/насилием нужно так же прогнать через это решение, прежде чем добавлять в Top 100.

| Работа | Правило |
|---|---|
| **L'Origine du monde** (Courbet) | Полностью исключена из Kids mode. Поле `kidsModeExcluded: true` в `data.js`. Карточка в Kids mode показывает нейтральный текст «Switch to Normal mode to view this artwork» (`AURA_STRINGS.kids_mode_excluded`) вместо why/where/rarity — Kids-текст для неё принципиально не пишем. |
| **The Birth of Venus** (Cabanel, `orsay_rf_273`) | Остаётся в Kids mode. Есть отдельные `whyKids`/`whereKids` — фокус на мифе (рождение Венеры) и технике (академическая живопись, путти), не на теле. |
| **Dante and Virgil in Hell** (Bouguereau, `orsay_rf_2010_8`) | Остаётся в Kids mode. Отдельные `whyKids`/`whereKids` — фокус на сюжете (Данте и Вергилий как рассказчики, путешествие по воображаемому загробному миру), не на драке/насилии. |
| **Tahitian Women on the Beach** (Gauguin, `orsay_rf_2765`) | Остаётся без ограничений во всех режимах. И `why` (Normal), и `whyKids` теперь соразмерно упоминают колониальный контекст периода творчества Гогена на Таити. Более тёмный биографический контекст (отношения с несовершеннолетними) сознательно не выносится в Kids-текст — не подходит для семейного продукта ни в каком виде.

Механика в коде: `renderCard()` в `app.js` при `state.mode === "kids"` сначала проверяет
`artwork.kidsModeExcluded` (если true — показывает нейтральное сообщение и прячет
блоки Where/Rarity), иначе использует `artwork.whyKids`/`artwork.whereKids`, если они
заданы, и только потом падает обратно на обычные `why`/`where`. У всех остальных 96 работ
`whyKids`/`whereKids` просто нет — для них Kids mode совпадает с Normal, как и раньше.

## Камера на телефоне / в другой сети

Команды запуска — см. блок Setup выше. Отдельная заметка про камеру: на телефоне
открой фронтенд через `https` или через адрес компьютера в локальной сети — у
большинства браузеров камера не работает на `http://` с внешнего IP, только на
`localhost` или `https`.

Порт backend — `8090` (не `8000`): у некоторых локальных окружений порт 8000 занят
или заблокирован; `BACKEND_URL` в `frontend/app.js` уже указывает на `localhost:8090`.
Если нужен другой порт — поменяй его в обоих местах (флаг `--port` у uvicorn и
`BACKEND_URL` в `app.js`).

## web/ — новый фронтенд ELYIO (Next.js), готовится на смену PWA

Полный визуальный ребрендинг AURA → ELYIO по дизайн-системе из `design/`
(`ELYIO-FINAL-PROMPT.md`, `ELYIO-design-system.md`, `ELYIO-iPhone-WoW-Design-System.html`).
**Backend не менялся** — те же эндпоинты (`/v1/recognize`, `/v1/visits/*`,
`/v1/artworks/{id}`), тот же контракт, тот же каталог 101 работы. Меняется только
визуальный слой и стек фронтенда (Next.js 16 / App Router / Tailwind v4 вместо
vanilla JS).

**`frontend/` (старый PWA) остаётся рабочим fallback'ом и не тронут.** Переключение
на `web/` как основной фронтенд — отдельное решение, ещё не принято; до этого момента
оба фронтенда работают параллельно с одним и тем же backend.

```bash
cd web
npm install
cp .env.local.example .env.local   # NEXT_PUBLIC_BACKEND_URL=http://localhost:8090
npm run dev
```

- `http://localhost:3000/app` — рабочее приложение (5 экранов, реальный state
  machine, реальный захват кадра с камеры и вызовы backend — `lib/api.ts` бьёт в те
  же эндпоинты, что и старый `app.js`).
- `http://localhost:3000/` — desktop landing / design-system reference page
  (sticky-навигация, scroll-spy, 5 экранов в iPhone-рамках) — переиспользует те же
  React-компоненты экранов, что и `/app`, просто с демо-данными вместо живого backend,
  так что витрина не может визуально разойтись с настоящим приложением.

Что перенесено 1:1 из старого фронтенда (не просто переизобретено по картинке):
- Content policy Kids mode (L'Origine du monde исключена, Cabanel/Bouguereau —
  мифология вместо тела, Gauguin — честный колониальный контекст) — `lib/artworks.ts`
  (`isExcludedInKids`, `resolveCardText`), логика идентична `renderCard()` в `app.js`.
  См. раздел "Content policy — Kids mode" выше — работает в `web/` так же, как в `frontend/`.
  Плюс: логика навигации между экранами (`↑`/`✕`/`←`) взята из `data-nav` в
  `frontend/index.html`, а не придумана заново.
- Полный текст обязательного disclaimer'а под ценовой оценкой (§11) — `lib/i18n.ts`
  (`estimate_disclaimer`), дословно из старой artwork-card.
- EN/FR/zh-Hans локализация — язык (`locale`) и режим (`mode`: Normal/Simple/Kids) это
  две независимые оси, переключение языка не сбрасывает режим и наоборот.
- `estimate.low/high` остаются `null`, пока редактор не проверит работу (§8.4) — нигде
  в `web/`, включая demo-данные на landing page, не выдуман ни один ценовой диапазон;
  бейдж честно показывает "Pending review".

### Установка на телефон ("Добавить на экран Домой")

`web/` — такой же устанавливаемый PWA, каким был `frontend/`: manifest, service worker,
иконки.

- `web/public/manifest.json` — `start_url` и `scope` оба указывают на `/app`, а не на `/`:
  иконка на экране телефона всегда открывает рабочее приложение, а не design-system
  витрину для разработчиков (это была явная развилка — по умолчанию логично было бы
  оставить `scope: "/"`, чтобы PWA-режим работал на обеих страницах, но здесь это
  осознанно уже, чтобы установленное приложение никогда не показало витрину).
- `web/public/icons/` — 4 PNG (192/512 × any/maskable), сгенерированы программно (Pillow),
  логотип "E" на чёрном фоне — та же идея, что и бейдж "E в чёрном круге" из дизайн-системы:
  сам круг рисует ОС при наложении маски на иконку, поэтому в файле не круг, а полноразмерный
  чёрный квадрат с белой "E" (тот же принцип, что и в старом `frontend/icons/icon-*.png`,
  которые тоже были просто "чёрный фон + белая буква", а не буквально нарисованный кружок).
- `web/public/sw.js` — минимальный cache-first-with-fallback service worker, по структуре
  идентичный старому `frontend/sw.js`; регистрируется из `components/ServiceWorkerRegister.tsx`
  (клиентский компонент, смонтирован в `app/layout.tsx`) с явным `scope: "/app"`.

Проверено через `fetch()`/`navigator.serviceWorker` вживую (эквивалент DevTools →
Application → Manifest): `manifest.json` отдаётся 200 и парсится, все 4 иконки отдаются
200 `image/png`, service worker регистрируется, активируется и берёт страницу под контроль
(`navigator.serviceWorker.controller` не `null`) — на `localhost` все критерии installability
выполнены (secure context на `localhost` есть по умолчанию, даже без HTTPS).

**Важный нюанс, которого не было явно в заметке про старый PWA**: и Service Worker, и
`getUserMedia` (камера) требуют secure context — по спеке это `https://` **или** буквально
`localhost`/`127.0.0.1`. Обычный `http://192.168.x.x:3000` (адрес компьютера в локальной
Wi-Fi сети) под это исключение не попадает, так что открыв фронтенд на телефоне по такому
адресу через голый HTTP, ты, скорее всего, увидишь работающий UI, но ни камера, ни
"Добавить на экран Домой" реально работать не будут (SW тихо не зарегистрируется). Два
рабочих варианта проверить это на телефоне:

```bash
# Вариант 1 — HTTPS с самоподписанным сертификатом прямо из Next.js:
cd web
npm run dev -- --experimental-https
# Открой https://<адрес-компьютера-в-Wi-Fi>:3000/app с телефона (сертификат
# самоподписанный — браузер попросит подтвердить исключение один раз).
```

```bash
# Вариант 2 — задеплоить (Vercel/любой хостинг с HTTPS по умолчанию) и открыть
# реальный https-адрес на телефоне.
```

На обоих путях: Chrome/Safari покажет "Добавить на экран Домой" — иконка "E на чёрном
фоне" появится как у обычного приложения, откроется сразу `/app`.

Известное ограничение на момент ребрендинга: живой сквозной тест (реальная камера →
реальный backend с `OPENAI_API_KEY` → реальная карточка) не был прогнан в этой сессии —
на машине, где вёлся ребрендинг, в моменте оказался заблокирован bind сокетов на уровне
ОС (не специфично для Python/uvicorn — тот же bind падает и из чистого .NET/PowerShell),
из-за чего backend не поднялся локально. Сам стейт-машин и вызов `/v1/visits` со всеми
правильными полями подтверждены живьём в браузере (запрос реально уходит на
`localhost:8090`, просто получал `503`, пока backend не запущен) — контракт и обработка
ошибок рабочие, но полный цикл с реальным распознаванием стоит перепроверить на чистой
машине перед тем, как считать `web/` готовым к переключению.

## Деплой backend на Fly.io

`backend/` готов к деплою: `Dockerfile` (Python 3.11-slim, uvicorn на `0.0.0.0:8080`),
`fly.toml` (app name-плейсхолдер `elyio-api`, `primary_region = "cdg"` — Париж, ближайший
к Musée d'Orsay регион Fly; если недоступен при `launch` — `ams` или `lhr`), `.dockerignore`
(исключает `venv/`, `.reference_cache/`, `__pycache__/`, `test_photos/`, `.env`, `.git`).

CORS в `app/main.py` сужен с `allow_origins=["*"]` до конкретного списка:
`https://elyio.vercel.app`, `https://elyio.co`, `https://www.elyio.co` и
`http://localhost:3000` (для локальной разработки `web/`). Если домен на Vercel/своём
хостинге в итоге будет другим — добавь его в этот список.

Сам деплой (`flyctl deploy`) я не запускаю — нужна твоя авторизация в Fly. Команды по
порядку, все из `backend/`:

```bash
cd backend

# 1. Логин в Fly (откроет браузер)
flyctl auth login

# 2. Регистрация приложения в Fly БЕЗ перезаписи уже готовых fly.toml/Dockerfile
#    и без немедленного деплоя (секреты выставим на следующем шаге):
flyctl launch --copy-config --no-deploy --yes
# --copy-config говорит flyctl использовать уже существующий fly.toml как есть,
# вместо того чтобы предлагать пересоздать его; --no-deploy — зарегистрировать
# приложение, но не деплоить прямо сейчас. flyctl всё равно может задать 1-2
# вопроса (например, в какой организации Fly создать приложение) — это нормально.
# Если имя "elyio-api" уже занято другим пользователем Fly (имена глобально
# уникальные) — flyctl об этом скажет; поменяй `app = "elyio-api"` в fly.toml
# на другое имя и повтори команду.

# 3. Секрет с ключом OpenAI — впиши сюда СВОЙ реальный ключ вместо плейсхолдера:
flyctl secrets set OPENAI_API_KEY=<вставь-свой-настоящий-ключ-здесь>

# 4. Деплой:
flyctl deploy
```

После `flyctl deploy` публичный URL — `https://<app-name>.fly.dev` (с именем из
`fly.toml`, т.е. по умолчанию `https://elyio-api.fly.dev` — flyctl также печатает его
в конце вывода `deploy`, и его всегда можно посмотреть через `flyctl status` или
`flyctl info`). Этот URL и есть значение для `NEXT_PUBLIC_BACKEND_URL` в настройках
окружения на Vercel (см. раздел про `web/` выше).
